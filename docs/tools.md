# Shape tools, Crop tool, Free Transform modifiers, Merge Down, and tool icons

Small tool/command behaviors that don't have their own doc. Selection tools live in [selection-tools.md](selection-tools.md); brushes in [brushes.md](brushes.md); the text tool in [text-tool.md](text-tool.md). The vector side of the shape tools (Shape/Path modes, pen, path editing, vector masks, Paths panel, shape library) lives in [vector-tools.md](vector-tools.md); this page covers the legacy Pixels-mode raster behavior, which must stay byte-identical.

## Clipboard pixel placement

- Edit > Paste (`edit.paste`, Ctrl+V) centers copied/cut selection pixels and external clipboard images on the active canvas viewport, using the current pan and zoom. Each axis is clamped so the pasted rectangle fits inside the document.
- Edit > Paste in Place (`edit.paste_in_place`, Ctrl+Shift+V) uses the selection's original document coordinates, including across documents, with the same bounds clamp. External images have no source coordinates and use the viewport center.
- Pasting preserves pixel dimensions and content. If the pixels exceed the canvas on an axis, that axis is centered with overflow instead of being resized or cropped. Both commands clear the selection in the paste history entry; Undo restores it and Redo restores placement.
- Both commands insert directly above the topmost selected layer, preserving the copied stack's order. A selected child keeps the paste in its folder; a selected folder places it above that folder. With no selected rows, paste appends at the document top. This applies to pixels, whole layer trees, and SVG; the topmost pasted layer becomes active and selected. The `ui_paste_inserts_above_topmost_selected_layer` and `ui_paste_above_selected_folder_or_at_top_without_selection` tests cover placement and undo/redo.
- The pixel placement code lives in `MainWindow::paste_clipboard` (`main_window_layer_ops.cpp`). Whole editable layer trees and SVG use their separate preserving clone/import paths. Palette and color-picker focus retain their color paste routing.
- Coverage: the `paste` UI filter includes viewport placement, all four edges, cross-document coordinates, oversized pixels, the actual shortcut, document/channel guards, external clipboard replacement, and undo/redo.

## Crop tool

Photoshop-style interactive crop (hotkey C; `tools.crop`). Session code in canvas_widget_crop.cpp; commit in `MainWindow::commit_crop_rect` (main_window_layer_ops.cpp), modeled on `crop_to_selection`.

- Drag lays out a document-space rect; nothing shows before the first drag, and a sub-drag click creates no session. With a rect pending: the 8 handles resize (reusing `transform_handle_at`, Rotate mapped to None), the interior moves (`snapped_rect_delta`), arrows nudge (Shift = 10 px), a drag off the box ROTATES it about its center (the straighten gesture; Shift snaps 15 degrees, a mere click changes nothing, Esc first to lay out a new rect; hover off the box shows `crop_rotate_cursor()` from tool_cursors.cpp as the hint), Enter or the options-bar check commits, Esc or the X cancels.
- A rotated box straightens on commit through the 4-arg `crop_document(doc, rect, angle, extension_color)`: result pixels sample the document through the inverse rotation about the box center (bilinear for 8-bit, nearest otherwise), text/smart-object/vector data ride the same affine, exposed areas follow the crop fill rules (Background fill color, transparency plus rgba8 promotion elsewhere), and angles under 0.01 degrees take the exact unrotated path. Handle drags on a rotated box run the axis-aligned edge math in the box's own frame; snapping is skipped while rotated (guides assume axis-aligned edges).
- The rect may extend past the canvas; commit expands the document through the 3-arg `crop_document(doc, rect, extension_color)` (document_geometry.cpp). A contained rect takes the exact legacy per-layer path; an expanding one keeps tight buffers on ordinary layers and rebuilds only a pixel layer literally named "Background" canvas-sized via `resize_layer_to_canvas`, filled with the background color at commit. Channels ride `resize_document_channel_canvas` (Spot new area 255, others 0). The 2-arg `crop_document` still clamps to the canvas: the script API relies on that contract.
- Switching tools, locking edits, or swapping documents CANCELS a pending crop (never commits, unlike Free Transform): an accidental switch must not resize the document. Re-clicking the Crop palette button keeps the session (`set_tool` tears down only on an actual tool change). Focus loss ends in-flight drags but keeps the session.
- Shift while dragging out constrains 1:1 (marquee-style latch, toggleable mid-drag); options-bar Ratio W : H fields (`tools/cropRatioWidth`/`tools/cropRatioHeight`, persisted; both > 0 to constrain) override Shift, always bind corner drags, and re-center the derived axis on edge drags. A ratio change never retro-resizes a pending rect. Shift on a corner with no ratio holds the drag-start aspect. `transform_drag_keeps_aspect` deliberately does not apply: crop is a drag-rect tool, not a transform session.
- The Ratio preset combo (`cropRatioPresetCombo`) writes into the W : H fields, which stay the source of truth: index 0 "None" and the last index "Custom" are fixed anchors (`sync_crop_ratio_preset_combo` derives the row from the field values and shows Custom for anything unmatched), "Original Ratio" reads the active document reduced by gcd at selection time, and Clear resets to None.
- `crop_drag_rect` is the third deliberately-unmerged twin of `marquee_selection_rect`/`shape_drag_rect`; unlike the marquee, its anchor is never edge-clamped (the pasteboard is legal). Spacebar repositions a drag-out in flight.
- Overlay (`draw_crop_overlay`): QRegion-with-hole shield at rgba(0,0,0,120) plus rule-of-thirds cosmetic line pairs, deliberately unthemed like the marching ants; the W x H readout rides `draw_drag_size_readout`. Full-widget repaints during crop drags are accepted (the shield spans the viewport).
- Plain C moved here from `image.crop_to_selection` (August 2026); that menu command keeps its persisted id but ships with no default shortcut, like Photoshop's Image menu.
- Coverage: core `crop_document_expanding_*`/`crop_document_mixed_crop_and_expand`/`crop_document_contained_rect_matches_two_arg_overload` (document_ops_filters_tests.cpp); UI `ui_crop_*` (crop_tool_tests.cpp).

## Shape tools (Rectangle/Ellipse/Line)

- Rectangle/ellipse honor brush Opacity/Soft through the signed-distance renderer in pixel_tools.cpp.
- Options-bar Style/Width/Height are deliberately session-only (mirrored via `current_shape_*`, never persisted). The row is registered pixel-only: the vector modes hide it and show the active shape's W / H instead ([vector-tools.md](vector-tools.md)). With Style Normal the Width/Height spins are greyed out (the marquee's twin row greys the same way); Fixed Ratio and Fixed Size enable them.
- A Pixels-mode click keeps the legacy 1 px commit (its `begin_edit` snapshot is pushed at press); the vector modes open the Create dialog instead. Coverage: `ui_shape_tap_*`, `ui_shape_style_row_is_pixel_only_and_greys_size_at_normal`.
- Alt = draw-from-center, so Rectangle/Ellipse are exempt from the Alt temporary-eyedropper (the two meanings fight).
- Mode is always the first options-bar item for the shape tools (built before the shared brush controls), so switching to Pixels never shifts it. Coverage: `ui_options_bar_mode_combo_stays_first_for_shape_tools`.
- ALL constraint math lives in `CanvasWidget::shape_drag_rect()` — it intentionally duplicates `marquee_selection_rect()` (selection-only concerns, separately pinned). Do not merge them.
- The Fill command has its OWN persisted Opacity/Soft (`tools/fillOpacity`/`tools/fillSoftness`, default 100/0); tests laying down setup color call `use_solid_fill_settings(canvas)`.
- Coverage: `ui_shape_fill_and_corner_radius_apply_to_new_documents` also pins the `current_*` mirror pattern from [ui-conventions.md](ui-conventions.md).

## Free Transform modifiers

Corner handles scale proportionally on their own and Shift releases the lock, matching Photoshop CC 2019 and later. The preference `input/shiftKeepsTransformAspect` (default `false`, Preferences > Application, `preferencesTransformShiftAspectCheck`) restores the older pairing, where a plain corner drag distorts and Shift holds the ratio. It is a persisted identifier and rides the pen-input load/save/apply trio in main_window_preferences.cpp, so `configure_canvas` and the Preferences accept loop both push it onto every canvas.

- Both sessions decide through one predicate, `CanvasWidget::transform_drag_keeps_aspect(modifiers)` (canvas_widget_transform.cpp): `shift == shift_keeps_transform_aspect_`. The pixel session calls it from `update_free_transform_preview`, the path session from `handle_path_transform_move` (canvas_widget_vector_tools.cpp). The two resize algorithms differ deliberately (anchor plus ratio versus box-local dominant axis); the shared predicate is what stops their modifier semantics drifting apart. Never reintroduce an inline `Qt::ShiftModifier` test for a resize.
- Edge handles (Top/Right/Bottom/Left) scale one axis in every mode. Only corners consult the predicate.
- While a Free Transform, Warp, or path transform session is pending, the Shape Appearance, Layer Style, and adjustment-layer dialogs refuse to open (`refuse_layer_dialog_during_transform`, a status hint to press Enter or Esc first). Their edits used to land under the baked session preview and only surface at commit (September 2026). Coverage: `ui_layer_dialogs_refuse_during_transform`.
- Shift on the rotate handle still snaps to 15 degrees in both sessions and both modes; it is a separate modifier test in the same functions.
- The options-bar link button (`freeTransformLinkScaleButton`) mirrors the W% and H% spin boxes only. It does not reach handle drags.
- The session start status line reports the active pairing, so both sentences are translated strings.
- Shift on the shape and marquee tools remains a 1:1 square/circle constraint on a new shape (`shape_square_constrained_`, `selection_square_constrained_`); that is unrelated and unchanged.
- A text layer's session rect is its whole raster (`move_layer_transform_local_rect`: a box layer's frame, a point layer's line box), the same rect the passive Move-tool controls draw, like Photoshop's paragraph-text box. Other layers use the opaque pixel rect. The two must agree because a handle drag sets the rect corner to the absolute mouse position: a session started on the smaller ink rect while the grabbed handle sat at the frame corner stretched the ink to the frame on the first move (September 2026, box text after Image Size went "instantly giant"). `ui_box_text_transform_handle_grab_keeps_ink_size` pins it.
- The rotate handle turns the box about the reference point (the options-bar Pivot combo, `transform_reference_point_`; `set_transform_reference_point` repaints the session box so the marker moves at once), like Photoshop: `update_free_transform_preview` measures the drag angle from `transform_reference_position(start rect, start angle)` and moves the center to `pivot + R(delta)(C0 - pivot)`. With `a` the anchor offset, `C0 - pivot = -R(start)a`, so `C1 + R(new)a` is the pivot again and the reference position is invariant. Numeric edits already pivoted there (`set_transform_controls_state`). `draw_free_transform` draws the reference marker (circle plus crosshair) during a session only; the passive Move box stays a plain frame, as in Photoshop.
- Scale handles compute in the box's own frame: the snapped pointer is unrotated about the drag-start center, the edge/corner setters and the Shift aspect block run on an axis-aligned local rect, the flip signs read the raw local rect, and the center rotates back out. At angle 0 this is the old world-space math exactly, so unrotated drags are byte-identical.
- Alt on a scale handle scales about the reference point (`transform_drag_scales_about_reference`, the Shift predicate's sibling): per moving axis the factor is `(pointer - r) / (handle - r)` in local coordinates and the center lands at `r(1 - f)`; a reference sitting on the dragged edge keeps the plain result for that axis; corners under the aspect lock share the axis the pointer pulled harder. Shift or Alt pressed or released mid-drag replays the preview at the last pointer position, and the modifier cursor filter skips `dragging_transform_`.
- Drag readout (`view/showTransformValues`, default on, Preferences > Application `preferencesShowTransformValuesCheck`, pushed to every canvas with the Shift-aspect pairing): `transform_drag_readout()` lists the reference point's X/Y plus the offset while moving (the Move tool uses the moving set's opaque union, `move_readout_base_rect_`), W x H plus the signed percentages while scaling, and the angle plus its delta while rotating. `draw_transform_drag_readout` paints only the change line (`canvas_lines`: the offset, the percentages, or the angle delta, no label) below-right of the pointer in the canvas HUD theme roles, while the status bar mirrors both lines (`lines`). Its panel rect joins the bounded drag repaints (`update_drag_readout_region`, [interactive-previews.md](interactive-previews.md)); release and cancel clear it. Text comes from `format_pixels`/`format_percent`/`format_degrees` in measurement_units.hpp.
- The options-bar X/Y/W/H/Angle fields are `UnitSpinBox`es ([ui-conventions.md](ui-conventions.md), [resolution-units.md](resolution-units.md)): X/Y are native px with percent relative to the document extent, W/H native percent with pixels relative to `TransformControlsState::original_size`, Angle degrees only. Typing a unit (or right-clicking the field) switches what the field displays; the linked W/H pair switches together. The link button still mirrors W and H.
- Coverage: `ui_transform_shift_frees_aspect_ratio_by_default`, `ui_transform_shift_aspect_preference_restores_legacy`, `ui_transform_shift_aspect_preference_defaults_to_off`, `ui_transform_shift_aspect_preference_persists_and_reaches_canvas`, `ui_transform_fields_accept_unit_tokens`, `ui_transform_rotate_drag_pivots_on_reference_point`, `ui_transform_alt_drag_scales_about_reference_point`, `ui_transform_handle_drag_on_rotated_box_uses_local_axes`, `ui_transform_drag_readout_shows_values`, `ui_move_drag_readout_reports_reference_and_delta`, `ui_transform_readout_preference_hides_hud`, plus the `unit_spin_box` group. The path session keeps its own center pivot and has no modifier test yet.

## Merge Down
- `MainWindow::merge_down` normalizes the selection, includes a single leaf's lower sibling, and routes selections containing vectors through the preserving planner and Merge Layers dialog. Compatible shapes merge immediately. The dialog offers separate vector/bitmap outputs, merges within each group, and separate vector paint categories. [layer-merging.md](layer-merging.md) owns the options, preservation boundaries, transaction, and scripting contracts.
- Bitmap-only selections retain the existing CPU-composited flattening path: hidden items contribute no pixels and are removed; the bottom visible layer keeps its id and name. Groups flatten in place, and pixels land within the canvas-clipped render bounds. Pattern resources accompany the scratch document. Position-only Background locking permits merge; image-pixel locking refuses it.

## Canvas right-click menu

The right mouse button on the canvas is the context-menu button and never pans (Seth, September 2026): panning is the middle button, the spacebar, the Pan tool, and the pen barrel button, which `dispatch_tablet_as_mouse` synthesizes as a middle-button drag. A right press records `context_press_pos_` (cleared by tool, lock, document, and focus changes through `close_canvas_context_menu`, and by a drag past `startDragDistance`); a release within that distance calls `CanvasWidget::show_canvas_context_menu`, the one builder for every canvas menu. Path tools get `canvasPathContextMenu` ([vector-commands.md](vector-commands.md)). Everything else gets a popup `canvasContextMenu` whose first section is the Move tool's layers-under-the-pointer entries ([layer-panel.md](layer-panel.md)) and whose second, present when the click landed on the selection, is `MainWindow::selection_context_actions_` (Remove Object, Fill, Clear, Stroke, Deselect, Inverse: the menus' own QActions, nullptr = separator, supplied through `set_selection_context_actions_callback`). No section, no menu. Alt+Right stays the brush adjust drag, a right-click on a ruler stays the unit menu, and the MCP activity overlay pans only with the middle button or Space. Coverage: `ui_right_drag_does_not_pan_canvas`, `ui_selection_context_menu_offers_remove_object`, `ui_move_layer_menu_preserves_pan_and_cancels_stale_clicks`, `ui_path_context_menu_edits_anchors`, `ui_pen_barrel_button_pans_instead_of_painting`.

## Tool palette layout

- Built imperatively in `MainWindow::build_tool_palette()` (main_window_actions_tool_palette.cpp, the tool-palette phase of `create_actions()`); order is the construction order, in separator-delimited clusters: select (Move, Marquee, Lasso, Wand, Crop), paint (Brush, Eraser, Gradient+Fill), retouch (Stamp, Healing, Smudge, Dodge), draw/type (Pen Tools, Path Tools, Shapes, Type), view (Pick, Hand, Zoom). The Pen Tools flyout (Pen P as default, then Add Anchor / Delete Anchor / Convert Point, unbound) sits directly before the Path Tools flyout (drawing and adjusting paths alternate constantly, so the two slots stay adjacent). Merging the Pen with the path-select tools was rejected because a flyout hides the tool you switch to most; the anchor tools joined the Pen (August 2026) because Photoshop users look for them there and P still re-selects the Pen. See [vector-commands.md](vector-commands.md).
- Below the tools, an expanding spacer pins the color cluster to the bottom edge, ordered FG swatch, BG swatch, Default Colors (D), Swap Colors (X), separator, Quick Mask. That order is deliberate for vertical overflow: QToolBar hides items tail-first into the extension button, so a short window loses Quick Mask first, then X and D, and the swatches last. The palette width is a 43 px minimum, never fixed, because clicking the extension arrow expands the bar into extra columns by temporarily widening it; a fixed width clamps that into a clipped sliver (see the standing rule in [ui-conventions.md](ui-conventions.md)). The expansion is a sticky toggle: stock Qt collapses it half a second after the pointer leaves the bar, so `ToolPaletteExpansionLock` swallows Leave while the extension button is checked, and picking a palette item leaves it open (an auto-collapse there ate the first click of the Zoom button's double-click-for-100%). While it is open, `ToolPaletteExpansionReservation` raises the bar's minimum width to the measured expanded width so the main-window layout reserves the extra columns and the canvas shrinks instead of being overlaid; each pass releases the minimum, re-measures, and re-pins so Qt can drop back to fewer columns when the window grows. The bar closes on an arrow re-click, or automatically once the window is tall enough that nothing overflows. Coverage: `ui_tool_palette_overflow_hides_quick_mask_before_swatches`, `ui_tool_palette_extension_button_expands_palette`, `ui_tool_palette_expansion_sticky_after_tool_pick`, `ui_tool_palette_expanded_zoom_double_click_sets_actual_pixels`, `ui_tool_palette_expansion_collapses_when_window_fits_again`.
- Tools sharing a slot go through the shared `create_flyout_tool_action` + `configure_tool_flyout` lambdas (eleven flyouts: marquee, lasso, wand, gradient+fill, stamp, healing [Healing Brush J / Spot Healing Shift+J / Patch unbound, default Healing Brush, see [healing.md](healing.md)], smudge/detail, dodge/tone, pen tools [Pen P / Add Anchor / Delete Anchor / Convert Point, default Pen], shape [Line/Rect/Ellipse/Polygon/Custom Shape, default Rect], path tools [Path Select A / Direct Select Shift+A]). Tools whose gestures the name does not explain also carry a two-line tooltip (`tool_tooltip_source`) and a status-bar activation hint (`tool_activation_hint_source`). The flyout swaps the button's default action on each member action's `triggered`, which also covers hotkey activation.
- Every flyout button sets the `toolFlyout` Qt property; the app stylesheet keys the corner-triangle `::menu-indicator` and its sizing on `QToolButton[toolFlyout="true"]`, so a new flyout only needs the property (via `configure_tool_flyout`), not a new QSS selector. Coverage: `ui_stamp_and_gradient_flyouts_swap_tools`.
- A flyout opens two ways: press-and-hold (`QToolButton::DelayedPopup`; the delay is `SH_ToolButton_PopupDelay` from `InteractionHintsStyle` in `src/app/main.cpp`, 200 ms instead of Qt's 600) or a left double-click (`configure_tool_flyout` installs a `MouseDoubleClickFilter` that calls `showMenu()`, because Qt otherwise routes the pair's second press back to `mousePressEvent` and restarts the hold timer). The first click of the pair still selects the default tool. Coverage: `ui_tool_flyout_double_click_opens_menu`.
- Clone/Pattern Stamp (S / Shift+S) and Gradient/Fill (G / Shift+G) deliberately share slots like the other paired-shortcut groups; Clone and Gradient are the defaults.

## Tool palette icons

- Original SVGs at `src/ui/icons/tool-*.svg` (32x32, `#dce2eb` strokes, at most one non-load-bearing `#74c0ff` accent). Generic metaphors, no Photoshop geometry, so the license stays clean.
- QtSvg renders a Tiny-1.2 subset only, and a typo'd qrc alias renders EMPTY silently — review with `patchy_ui_visual_tests.exe ui_tool_palette_icons` (writes contact-sheet artifacts, checks per-icon coverage + pairwise distinctness).
- Clone keeps the classic rubber-stamp silhouette; Pattern Stamp is deliberately a different silhouette (stamp knob over a large checkerboard tile) because a small in-base detail was indistinguishable from Clone at the palette's 20px render size. Keep any future pair of related tools distinct in SILHOUETTE, not just in accent color. The healing flyout follows the same rule: bandage (Healing Brush), circle with burst ticks (Spot Healing), rotated stitched square (Patch). The pen flyout: nib drop (Pen), a curve with a hollow anchor plus a + or - accent (Add/Delete Anchor), a corner whose anchor sprouts a handle (Convert Point).
